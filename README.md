# dsh-model-fingerprint

模型指纹检测插件：让这台 DSH 里**已经接入的任意模型**凭第一反应写下约 300 个
1 到 355 的整数，再与内置的模型参考库比对，判断它背后到底是哪家的模型。

功能对应 [lm.ikale.io](https://lm.ikale.io/#/?mode=api) 的 API 模式，但取样走的是
DSH 自己的 `llm` 服务 —— 你不需要填 Base URL、不需要贴 API Key，模型列表就是
「设置 → 模型」里那些已经接好的服务商与模型。面板挂在侧边栏（「自动化任务」下方），
全部计算在本地完成。

## 它能做什么

- **在侧边栏打开**：左侧导航「自动化任务」下方多一行「模型指纹」，点开就是这个面板，
  不占用设置页。
- **手选模型检测**：从已接入的服务商里挑一个模型（可再挑推理强度），
  点「开始检测」，插件随机抽 1–3 条提示词发给它，解析回复里的整数序列，
  输出参考库排名与校准概率。
- **关掉页面也继续跑**：作业在宿主进程里执行，关标签页、切走面板都不影响；
  重新打开面板会自动接回那次作业，进度和结果照常出现。
- **用当前对话的模型**：一键把选择器切到当前会话正在用的那个 provider/model。
- **参考库浏览**：`/library` 列出清单里全部参考模型的家族与样本数。
- **历史记录**：每次检测结果都按「供应商 / 模型」存到本地（最多 400 条），
  落在下面的「总览」里——每个模型行显示它最近一次的结果与时间。

## 原理

不同模型在「随手写一串随机数」这件事上有稳定且可区分的习惯：数字的频次分布、
分块后的形状、位置核、相邻数字的转移结构都不同。插件把每条回复转成
`355 + 74 + 102 + 220 = 751` 维特征，投影到参考库的子空间里算距离，
再融合频率排名、最近参考样本距离与位置模型得分，最后用 `ranking-temperature`
校准成闭集概率。

检测前会先做形状判定：相邻数字的自相关 ≤ -0.23 或小步占比 ≤ 0.05 才算「像模型写的」，
否则判为 `not_model`，不生成排名。

样本数决定输出形态：

| 样本数 | 结果 | 概率 |
| --- | --- | --- |
| 1–2 条 | `partial` | 只有相对分数（`probability: null`） |
| 3 条 | `scored` | 有校准概率（`reference_calibrated`） |

## 安装

```powershell
# 在 DSH 里
plugin_manager action=install_bundle target="D:\IT\DSH工作区\DSH插件\dsh-model-fingerprint"
```

安装后重启会话，侧边栏「自动化任务」下方会出现「模型指纹」这一行，点它进入面板。
改动 `client.js` 后需要刷新页面（本机没跑 `dev:web` 时不会热更新）；改动 host 侧
（`index.js` / `lib/`）后需要重启 DSH，或对插件做一次 disable → enable 让它重新 import。

## 界面

面板从上到下分六块：

1. **检测器状态**：就绪 / 不可用、参考库模型数、构建时间、大小，可强制刷新。
   刷新会从 `https://lm.ikale.io/data/` 重新下载并校验 sha256。刷新拿到的
   `bundle.json` 与检测器一起写进 `$DSH_HOME/storages/dsh-model-fingerprint/`，
   启动时把缓存与随包副本按 `built_at` 比新旧，取新的那一份（检测器只认清单里
   `sha256` 对得上的那个文件），所以**手动刷新过的模型库不会在重启后被打回随包版本**。
2. **选择模型**：服务商下拉 + 模型下拉 + 推理强度下拉（只有该模型声明了 effort 才出现），
   旁边有「用当前对话的模型」。列表来自宿主 `llm` 服务的 `listProviders` / `listModels` /
   `resolveModelInfo`，读不到的 provider 会带一行错误提示但不影响其它 provider。
3. **采样选项**：样本数 1/2/3、并行发送、宽松模式（取够目标数字就停）。
4. **开始检测**：进度条 + 每条样本的状态（等待 / 已发送 / 接收中 / N 个数字 / 无效）、
   停止按钮。跑完的样本会在状态后面跟一段**输出速度**（如 `10 个数字 · 43 tok/s`），
   全部跑完后运行区上方还会多一个「平均输出速度」的汇总条。
   速度的算法跟官方统计一致：`输出词数 ÷ 生成秒数`（`decode_ms` = 首个正文 token
   到流结束，**不含首字之前的等待**）；取不到 usage 或时长的那一条不显示速度。
   少数上游（尤其是转发的第三方接口）不逐字下发，而是憋到生成完一次性怼过来，
   这时「首字→结束」只剩几十毫秒，按解码窗口算会得到几千 tok/s 的假速度；
   解码窗口不到总时长一半的样本改用整段请求时长做分母，并在展开区注明
   「上游一次性下发，按整段耗时算」。
   宽松模式会提前截断正文，所以截断后还会继续读一小段（最多 12 秒 / 6000 字符）
   等 usage 到达，否则算不出速度。
   **检测结束后样本卡片不会消失**，点任意一张展开看这条的原始输出
   （期望多少个数字、实际取到多少个、输出速度与其依据、出错原因），再点一次收起。
   每张卡片右上角有 **重试**：只把这一条重新发一次，其它样本保留，回来之后拿
   「这条的新输出 + 其它有效样本」重新排名；重试失败时卡片标成无效并写清原因，
   已有排名不动。**几条样本可以同时重试**：点了几条就有几条在各自跑，正在跑的那几条
   显示「重试中」，其余卡片照旧可点，运行区会显示「正在重试 N 条样本」。
   每条跑完后先并回快照、再拿合并后的全部有效样本重新算一次排名，所以并发重试
   不会互相盖掉对方的结果。作业本身在宿主进程里跑，**关掉页面或切回对话都不会中断**；
   重新打开面板时它会问一次 `/active`，把还在跑的那次作业接回来接着显示进度。
   如果离开的这段时间作业已经跑完了，回来同样**看得到这次的样本卡片和排名**——
   宿主会留一份最近一次检测的结果，面板挂载时靠它复原，并在顶部提示「已恢复上一次的检测结果」。
   单条重跑的结果也会并回这份快照，所以切走再回来看到的是重跑之后的界面。
    复原出来的结果只要带上了校准概率，下面的总览里同一个模型那一行也会立刻换成
    「库内校准排名 · 置信度」，历史里还没有这一行也会补上，不用再测一遍；
    重跑补出概率时历史那一行同样会被替掉（点「清空记录」之后不补，直到下一次结果出来）。
5. **结果**：决策标签（库内校准排名 / 部分样本排名 / 不像语言模型的回答 / 样本不足）、
   有效样本数、所用 provider/model、最像的模型与置信度、8 条候选条形图。
6. **总览**：把已接入的模型按服务商分组列出（分组标题带「x/y 已测」计数），点标题展开
   或收起该组；组内每一行是模型名 + 这条模型最近一次的检测结果（结果 · 置信度 · 时间），
   没测过的写「未测试」。这一块同时就是历史视图——每个 provider/model 只显示最新一条
    （同一个模型再测一次会替掉旧行，不攒重复记录），
   右上角的「清空记录」清掉本地保存的所有历史。
   顶部的搜索框同时匹配「服务商名称 / id」与「模型名称 / id」子串：有输入时只留有命中的
   分组并默认展开，全部不命中显示「没有匹配的供应商或模型。」，清空后立刻还原成完整列表。

排名表的条形：有校准概率时按概率画；只拿到部分样本（`partial`）时没有概率，
此时按「相对分数 / 最高分」画，数字位显示 `—`，不会用名次伪造长度。

配置（provider/model/effort/样本数/并行/宽松）改动后静默落盘到
`$DSH_HOME/storages/dsh-model-fingerprint/state.json`；最近一次跑完的检测结果（`lastRun`）也写在同一份文件里，所以宿主重启之后重新打开面板，界面上那份结果仍然在。

## HTTP 路由

宿主半边注册在 `/dsh-model-fingerprint` 下，全部同源校验（跨站一律 403）：

| 路由 | 方法 | 说明 |
| --- | --- | --- |
| `/state` | GET | 配置、默认值、历史、检测器状态、当前对话选择、正在后台跑的作业 |
| `/active` | GET | 取当前正在跑的作业（页面重开时用它接回，`jobs` 列出全部并发中的作业）；另外回 `last`，即最近一次跑完的检测结果，用于面板切走再切回时复原 |
| `/catalog` | GET | 已接入的 provider 与模型 |
| `/model-info?provider=&model=` | GET | 单模型的推理强度、上下文窗口 |
| `/config` | POST | 保存配置 |
| `/challenges` | POST | 生成取样提示词（调试用） |
| `/detect` | POST | 起一个后台检测作业，返回 `jobId` |
| `/retry` | POST | 只重跑指定的那一条样本，返回 `jobId`（`mode=retry`），结果里带这张卡片与重新算好的排名；可以同时发多个 |
| `/job?id=` | GET | 轮询作业状态与结果 |
| `/cancel` | POST | 停止作业（会把它自己的与所有在跑的重试一起取消） |
| `/library` | GET | 参考库（当前那张清单里的全部模型） |
| `/refresh` | POST | 重新下载检测器数据（清单与检测器成对落盘到缓存） |
| `/history` | POST | 读取或清空历史 |

## 数据

`data/bundle.json` + `data/shared_detector.bin` 来自官方数据包（`lmfpd-data`，
`shared_detector.bin` 5090952 字节，sha256 `fe32914d…020c5f`），随插件一起分发，
离线可用。点「刷新数据」时会回落到 `https://lm.ikale.io/data/` 重新下载并校验，
**清单与检测器一起**缓存到 `$DSH_HOME/storages/dsh-model-fingerprint/`。
之后每次加载都把缓存与随包副本按 `built_at` 比一次新旧，用新的那份，
所以刷新过的库在重启之后不会被随包副本顶回去。

## 免责

检测结果是库内统计排序，不是身份证明。校准概率只在「这个模型确实在参考库里」的前提下有意义；
面对库外模型，它会给出最接近的那个，而不是「未知」。同一家的不同小版本（例如
`deepseek-v4.1-flash` 与 `deepseek-v4.1-flash-1017`）常常互为主要竞争者，看家族比看单一 id 稳。
